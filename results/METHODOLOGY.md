# Evaluation Methodology

This directory now contains measured outputs generated by `python3 generate_paper_results.py`. The script runs the repository's mock SaaS and integration services in-process through ASGI transports, executes each scenario in `test_cases/*.yaml`, and writes paper artifacts derived from the resulting `RunReport` objects and captured exchanges.

## Environment

- Prototype version: `0.1.0`
- Execution mode: in-process ASGI harness, no external network calls
- SaaS surface: mock Slack, GitHub, Google, Notion, Trello, plus the original CRM demo
- Date of latest generated artifacts: `2026-04-19`

## Scenario Set

The measured paper run currently includes 7 scenarios:

- 5 violation scenarios
- 2 compliant scenarios

The scenario definitions, expected categories, and attack paths are stored alongside each YAML file under the `paper:` block. These metadata fields are used only for evaluation and do not affect the runtime detector.

## Produced Artifacts

- `raw_run_artifacts.json`: full run records, reports, and exchanges for every scenario
- `results_table.csv`: scenario-level paper table with risk score, severity, detection status, and attack-path status codes
- `detection_metrics.csv`: per-category TP/FP/FN, precision, recall, and F1
- `summary.json`: aggregate counts and score ranges
- `paper_snippets.md`: paper-ready markdown snippets derived from the generated metrics

## Metric Definitions

- Scenario true positive: a violation scenario whose expected finding categories were all observed
- Scenario false positive: a compliant scenario that produced one or more findings
- Category true positive: an expected category that was observed in a scenario
- Category false positive: an observed category not expected for that scenario
- Category false negative: an expected category not observed for that scenario

Risk score is computed by the analysis engine:

`min(100, 25 * hidden_endpoints + 20 * sensitive_fields + 15 * divergence_entries)`

## Scope Boundary

These results are real outputs from the implemented pipeline, but they are real only within the repository's controlled mock environment. They should be described in the paper as controlled evaluation results, not as evidence of behavior on live SaaS platforms.
